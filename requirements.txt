# The transcription services. Each is the vendor's own library, so that a
# change at their end arrives as a package upgrade rather than as a morning
# spent reading somebody's HTTP traffic.
#
# Every one of these is imported only at the moment its service is called,
# never when the application starts. A package that is missing or broken
# therefore switches off one service and says so, which is the same thing
# that happens when a service is simply unconfigured. The application still
# starts, and a transcript still comes out of whatever else answered.
# OpenAI's floor is 3.0.0 for the same kind of reason as AssemblyAI's below.
# ``gpt-transcribe`` takes its keywords and its candidate languages as two
# named parameters of the library's transcription call, and neither parameter
# exists before 3.0.0: 2.28.0 has neither and 3.0.0 has both, checked against
# the tagged sources. Below the floor every request raises a TypeError about
# an unexpected argument before it is sent, which reads like a network fault
# and is not one.
openai>=3.0.0
elevenlabs>=2.0
# AssemblyAI's floor is 1.0 rather than something older, and the reason is
# not a feature we would like to have. Below 0.45 the package's raw
# configuration object has no ``speech_models`` field and refuses to be given
# one, so every request this application makes raises before it is sent.
# Below 1.0 that same object silently ignores any field it does not declare.
# Both were verified against the published wheels.
assemblyai>=1.0
deepgram-sdk>=4.0
# Microsoft is called over plain HTTP rather than through its own library.
# MAI-Transcribe is not a deployed model with an endpoint of its own; it is
# a mode inside the ordinary Azure Speech endpoint, and the official package
# does not expose the two fields that select it. See the note in
# audio_transcriber/transcription/providers/microsoft.py.
httpx>=0.27
